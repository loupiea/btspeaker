# 蓝牙音箱软件长期编程规划

更新日期：2026-07-22

## 1. 软件目标

本软件用于 ESP32-WROOM-32E 蓝牙音箱工程样机。第一阶段目标不是一次做完所有功能，而是按“板子可启动 -> BSP 抽象 -> 外设验证 -> 音频输出 -> 音源输入 -> 状态机整合 -> 长时间稳定性”的顺序，把每个硬件单元逐个跑通。

项目代码目录固定为：

```text
E:\loupi\project\btspeaker\software
```

BSP 板级支持包目录固定为：

```text
E:\loupi\project\btspeaker\software\bsp
```

## 2. 总体开发原则

- 先做可测功能，再做完整功能。
- 每次只验证一个硬件模块，避免多个故障混在一起。
- BSP 只放板子相关代码，包括引脚定义、GPIO、I2C、SPI、I2S、电源检测、按键、编码器、OLED、功放使能等。
- `main` 目录只负责应用入口、任务创建和系统状态机，不直接散落大量 GPIO 细节。
- 每个阶段都必须能通过串口日志观察结果。
- 所有新模块先提供最小测试程序，再接入整机状态机。
- 暂时不追求复杂 UI、播放列表、无损格式、Wi-Fi、App 控制和高级 DSP。

## 4. 阶段规划

### 阶段 A：基础工程与串口自检

目标：确认 ESP32 能启动、串口日志正常、Flash 正常。

当前状态：已完成最小串口心跳程序。

验收标准：

- 可以烧录。
- 串口监视器每秒看到 `alive tick`。
- 能看到芯片核心数、芯片版本、Flash 容量。

下一步：

- 确认 VS Code ESP-IDF 插件能稳定 Build / Flash / Monitor。
- 清理 `main.c`，把板级初始化逐步迁移到 BSP。

### 阶段 B：BSP 框架

目标：建立板级支持包，让所有硬件引脚和初始化函数集中管理。

首批文件：

```text
software\bsp\CMakeLists.txt
software\bsp\include\bsp_board.h
software\bsp\include\bsp_pins.h
software\bsp\src\bsp_board.c
```

首批内容：

- ESP32 引脚宏定义。
- `bsp_board_init()`。
- `bsp_board_print_info()`。
- 串口自检日志迁移到 BSP。

验收标准：

- `main.c` 中只调用 `bsp_board_init()` 和少量应用逻辑。
- 编译通过。
- 串口日志仍能正常输出。

### 阶段 C：GPIO、按键、编码器

目标：验证用户输入。

涉及硬件：

- 播放/暂停按键：GPIO13。
- 音源切换按键：GPIO14。
- 旋转编码器 A：GPIO34。
- 旋转编码器 B：GPIO39。

注意：

- GPIO34/GPIO39 只能输入，没有内部上下拉，必须依赖外部上拉。
- 按键建议按下接地，软件按低电平有效处理。

验收标准：

- 串口能打印按键按下/松开事件。
- 编码器顺时针、逆时针能稳定识别。
- 软件有基本消抖。

### 阶段 D：I2C 与 OLED

目标：验证 I2C 总线和 OLED 显示。

涉及硬件：

- I2C SDA：GPIO21。
- I2C SCL：GPIO22。
- OLED：SSD1306 128x64。
- 后续 ES8388 也共用 I2C 控制总线。

开发顺序：

1. I2C 扫描，确认 OLED 地址。
2. OLED 显示固定文字。
3. OLED 显示音源、音量、电池估算值和播放状态。

验收标准：

- 开机显示项目名。
- 转动编码器后 OLED 音量数值变化。
- 按音源键后 OLED 音源名称变化。

### 阶段 E：电源与电池检测

目标：读取电池电压，做简单电量估算。

涉及硬件：

- BAT_ADC：GPIO36。
- IP5306 由实体电源键控制，ESP32 首版不控制 IP5306 开关机。

开发内容：

- ADC 初始化。
- 电池分压换算。
- 电量百分比粗略估算。
- 低电压串口告警。

验收标准：

- 串口打印电池 ADC 原始值、电压值和估算百分比。
- OLED 显示电量。
- USB 供电、电池供电两种状态下读数合理。

### 阶段 F：I2S 输出与 MAX98357A 功放

目标：让 ESP32 输出测试音到 MAX98357A x2。

涉及硬件：

- I2S0 BCLK：GPIO26。
- I2S0 LRCLK：GPIO25。
- I2S0 DOUT：GPIO27。
- AMP_SD/MUTE：GPIO16。

开发顺序：

1. 初始化 I2S0。
2. 产生 440 Hz 或 1 kHz 正弦波/方波测试音。
3. 控制 AMP_SD/MUTE。
4. 增加数字音量。
5. 验证左右声道。

验收标准：

- 两个喇叭能分别出声。
- 音量可调。
- 静音控制有效。
- 低音量无明显爆音。

### 阶段 G：蓝牙 A2DP Sink

目标：手机/电脑通过蓝牙连接并播放音频。

开发内容：

- Classic Bluetooth 初始化。
- A2DP Sink。
- 蓝牙设备名。
- A2DP 音频数据送入 I2S 输出链路。
- 连接、断开、播放状态日志。

验收标准：

- 手机能搜索到设备。
- 可以配对连接。
- 可以播放音乐。
- 音量调节有效。
- 断开后系统不死机，可以重新连接。

### 阶段 H：TF/SD 卡播放

目标：读取 TF/SD 卡文件并播放 WAV/MP3。

涉及硬件：

- VSPI SCLK：GPIO18。
- VSPI MISO：GPIO19。
- VSPI MOSI：GPIO23。
- TF/SD CS：GPIO5。

开发顺序：

1. SPI 总线初始化。
2. 挂载 FAT32。
3. 枚举根目录文件。
4. 播放 WAV。
5. 增加 MP3 解码。

验收标准：

- 串口能列出 TF/SD 卡文件。
- 能播放测试 WAV。
- 能播放测试 MP3。
- 拔卡/无卡时系统不崩溃。

### 阶段 I：U 盘播放

目标：通过 CH376S 读取 U 盘并播放 WAV/MP3。

涉及硬件：

- VSPI SCLK/MISO/MOSI 与 TF/SD 共用。
- CH376S CS：GPIO15。
- CH376S INT 首版不接 ESP32，通过 SPI 轮询。

开发顺序：

1. CH376S SPI 通信自检。
2. 读取芯片版本。
3. 检测 U 盘。
4. 枚举文件。
5. 播放 WAV/MP3。

验收标准：

- 串口能识别插入 U 盘。
- 能列出文件。
- 能播放测试音频。
- 拔出 U 盘后系统不死机。

### 阶段 J：AUX 输入与 ES8388

目标：通过 3.5mm AUX 输入音频，进入 ESP32 后再输出到 MAX98357A。

涉及硬件：

- ES8388 I2C：GPIO21/GPIO22。
- ES8388 MCLK：GPIO33。
- I2S1 BCLK：GPIO32。
- I2S1 LRCLK：GPIO17。
- I2S1 DIN：GPIO35。

开发顺序：

1. I2C 识别 ES8388。
2. 配置 ES8388 ADC。
3. I2S1 采集音频。
4. 转发到 I2S0 输出。
5. 调整增益和底噪。

验收标准：

- 电脑/手机 AUX 输入能从喇叭播放。
- 音量可控。
- 无明显削波、底噪不过分。

### 阶段 K：音源状态机

目标：把蓝牙、TF/SD、U 盘、AUX 统一成一个稳定的整机逻辑。

音源枚举：

```c
typedef enum {
    AUDIO_SOURCE_BT = 0,
    AUDIO_SOURCE_SD,
    AUDIO_SOURCE_USB,
    AUDIO_SOURCE_AUX,
} audio_source_t;
```

核心逻辑：

- 音源切换键循环切换。
- 当前音源独占音频输出。
- 切换音源时先静音，再停止旧音源，再启动新音源，最后解除静音。
- OLED 同步刷新。
- 串口打印状态变化。

验收标准：

- 任意音源切换不死机。
- 切换时爆音可接受或无明显爆音。
- OLED、串口、实际播放状态一致。

### 阶段 L：稳定性与产品化

目标：让样机可以作为展示项目长期运行。

测试项目：

- 连续蓝牙播放 2 小时。
- 电池供电播放。
- USB-C 边充边播。
- 音源反复切换。
- 插拔 TF/SD 卡。
- 插拔 U 盘。
- 最大音量短时测试。
- 中等音量温升测试。

验收标准：

- 不死机。
- 不异常重启。
- 不明显过热。
- 日志能定位异常原因。
- 测试记录保存到项目文档。

## 5. 推荐近期 10 个编程任务

1. 修好本机 ESP-IDF 编译/烧录环境，确保 `idf.py build` 或 VS Code Build 稳定可用。
2. 建立 `software\bsp` 组件。
3. 把当前串口自检迁移为 `bsp_board_print_info()`。
4. 在 BSP 中加入 `bsp_pins.h`，固化所有 GPIO 分配。
5. 写按键读取测试。
6. 写旋转编码器读取测试。
7. 写 I2C 扫描测试。
8. 写 OLED 显示测试。
9. 写电池 ADC 读取测试。
10. 写 I2S 测试音输出。

## 6. 每次开发的固定流程

每做一个模块，都按这个顺序：

1. 明确目标：这次只验证哪一个硬件或软件能力。
2. 写最小代码：只做到能观察结果。
3. 打印日志：成功、失败、关键参数都要能看见。
4. 上板测试：记录串口输出和现象。
5. 整理代码：把板级部分放回 BSP。
6. 写验收结论：通过、失败、下一步。

## 7. 当前下一步建议

下一步不要直接写蓝牙音频。建议先做：

```text
BSP 框架 + 引脚定义 + 保留当前串口自检
```

原因：

- 这是所有后续外设代码的地基。
- 现在 `bsp` 目录已经为空目录，正适合开始搭骨架。
- 做完后，`main.c` 会变干净，后续按键、OLED、I2S 都能复用 BSP。

建议下一个具体任务：

```text
创建 software\bsp 组件，并把当前 main.c 的板子信息打印迁移到 BSP。
```
