# 方案审查与修正记录

更新日期：2026-07-09

## 1. 本次审查目的

本次审查针对现有方案文档中的旧需求残留、互相矛盾、原理图风险表述和不准确说法进行修正，保证后续在嘉立创 EDA 画原理图时不会照着旧方案画错。

## 2. 已修正的问题

### 2.1 USB Audio 旧需求残留

问题：

- `02-技术方案.md` 中仍出现“USB 电脑音频输入电路”和“USB 音频单元”。
- 这与当前首版结论冲突：USB-C 只供电/充电，USB-A 只接 U 盘。

修正：

- 删除 USB Audio 作为首版自研单元的描述。
- 保留“首版不做 USB Audio，电脑有线输入走 AUX”的说明。

### 2.2 CH376S/CH376 混写

问题：

- 多处写成 `CH376S/CH376`，容易让原理图和采购时混用两个型号。

修正：

- 首版统一为 `CH376S 裸芯片`。
- `CH376` 只作为同系列备选，不再作为首版默认器件。

### 2.3 MAX98357A 输入描述错误

问题：

- `02-技术方案.md` 的功放设计内容里写了“输入 AC 耦合和增益设置”。
- MAX98357A 是 I2S 数字输入功放，不能按模拟功放输入那样画 AC 耦合。

修正：

- 改为 `I2S BCLK/LRCLK/DIN 输入和左右声道配置`。
- 保留 SD/MUTE、GAIN、供电去耦、I2S 串联阻尼等检查项。

### 2.4 TF/SD 与 U 盘插入检测冲突

问题：

- 路线图和测试计划中写了读取 TF/SD 插入检测、U 盘中断。
- 最新引脚分配中 `TF/SD CD` 和 `CH376S INT` 首版不接 ESP32，只预留测试点。

修正：

- 改为通过软件挂载/轮询识别 TF/SD 和 U 盘状态。
- 文档中明确 `TF/SD CD`、`CH376S INT` 首版只预留测试点。

### 2.5 IP5306 电源路径表述过满

问题：

- 部分文档把 IP5306 描述成完整“电源路径/负载共享”方案。
- 这容易在原理图设计和面试表达中说得过满。

修正：

- 改为：IP5306 做 1S 充电、5V 升压和充放电同步应用，首版必须按 datasheet 典型应用图连接。
- 边充边播作为首版重点实测项。
- 若实测出现重启、充电异常或温升过高，第二版再加外部负载共享、理想二极管或更强电源管理方案。

### 2.6 调试计划中 USB 角色错误

问题：

- 旧路线图中写了“焊 USB 部分，确认电脑枚举”和“USB 可被电脑识别”。
- 当前首版没有 USB Device 功能，不能作为电脑 USB 设备枚举。

修正：

- 改为 USB-C 只验证 5V 输入。
- USB-A 只验证 CH376S 识别 U 盘。

### 2.7 旧电源方案和旧 UI 残留复查

复查确认：

- 未发现仍把首版写成 12V、9V、2S、7.2V 或 TPA3110D2 的有效方案。
- 未发现仍把首版写成单声道。
- 未发现 TCA9555/PCF8574 作为首版必需器件。
- 未发现上一首/下一首作为首版独立按键。
- 未发现耳机/耳放作为首版输出功能。

## 3. 当前一致结论

- 首版为 2.0 立体声。
- 主控为 ESP32-D0WD-V3 裸芯片 + 16MB SPI Flash + 40MHz 晶振。
- 喇叭输出为 MAX98357A x2。
- AUX 输入为 ES8388 ADC/Codec。
- U 盘为 CH376S 裸芯片 + USB-A Host。
- TF/SD 和 CH376S 共用 VSPI，独立 CS。
- USB-C 只做 5V 输入和电池充电。
- 供电为 USB-C 5V + IP5306 + 1S 3.7V 2500mAh 电池 + SY8088IAAC 3.3V。
- 首版不加 PSRAM，不加 I2C GPIO 扩展器，不做耳机输出，不做 USB Audio。

## 4. 仍需原理图阶段继续确认

这些不是文档错误，但在画原理图前必须确认：

1. IP5306 所采购封装和典型应用图。
2. SY8088IAAC 电感、电容、反馈电阻具体值和封装。
3. CH376S 封装、供电电压、晶振/时钟要求。
4. ES8388 line-in 推荐电路、模拟电源滤波方式。
5. MAX98357A L/R、GAIN、SD/MUTE 具体接法。
6. USB-A 5V 负载开关型号。
7. ESP32 GPIO5/GPIO15 作为 SPI CS 时的默认上拉和启动电平复核。
