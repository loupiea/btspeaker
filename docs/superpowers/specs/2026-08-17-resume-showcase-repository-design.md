# 简历展示仓库发布规范

## 目标

将 `btspeaker` 整理为可直接放入简历的公开 GitHub 项目，展示 ESP32 蓝牙、TF 卡和 AUX 三种音频模式，并确保公开内容清晰、可构建且不包含敏感信息或本地产物。

## 发布范围

- 发布最新软件源码、对应自动化测试、必要硬件工程、BOM、Gerber 和方案文档。
- 删除旧的 U 盘播放模式及 CH376 播放驱动，README 只描述蓝牙、TF 和 AUX 三种模式。
- 保留硬件共享总线所需的 CH376 片选隔离代码，但明确其不属于当前播放功能。
- README 包含项目亮点、功能清单、硬件清单、系统架构、目录说明、构建步骤、TF 音频格式和演示素材入口。

## 不发布内容

- ESP-IDF `build/` 编译目录。
- 编辑器和开发容器个人配置：`.vscode/`、`.devcontainer/`、`.clangd`。
- 硬件软件自动备份目录、调试日志、Office 临时文件和操作系统缓存文件。
- 密码、Token、私钥、证书、Wi-Fi 凭据和个人隐私信息。

## Git 策略

- 保留当前分支 `codex/ch376s-spi-self-test`，不直接覆盖默认分支。
- 先提交本规范，再提交仓库整理、README 与功能代码。
- 推送前运行敏感信息扫描、Python 契约测试和 ESP-IDF 完整编译。
- 推送当前分支到 `origin`；是否合并默认分支由仓库状态和用户后续选择决定。

## 验收标准

1. Git 跟踪内容不含编译产物、编辑器配置、自动备份和调试日志。
2. README 能让面试官在几分钟内了解项目价值、本人工作和复现方式。
3. 自动化测试全部通过，ESP-IDF 固件能够完成编译和链接。
4. 敏感信息扫描未发现真实凭据。
5. 最新提交成功推送至公开 GitHub 仓库。
